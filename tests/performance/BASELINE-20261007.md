# 2026-10-07 단기 재현 기록

실제 EventRepository와 PostgreSQL 16, PCAPWriter를 사용한 연결 확인이다.
입력은 합성 패킷이며 정상 업무·악성 여부의 정답 레이블 검증은 아니다.
운영 DB·NIC·방화벽·외부 채널은 사용하지 않았다.

| 조건 | normal | unique-key |
|---|---:|---:|
| 요청 기간 | 10초 | 10초 |
| 목표 pps | 100 | 50 |
| 합성 경보 직접 주입 | 없음 | 초당 20건 |
| 생성한 패킷 | 1,000 | 500 |
| 저장 이벤트 | 139 | 342 |
| 입력 큐 app drop | 0 | 0 |
| 프로세스 CPU 시간 | 5.602초 | 5.319초 |
| 프로세스 peak RSS | 107.1MiB | 103.3MiB |
| 이벤트 루프 지연 표본 수 | 92 | 96 |

두 실행 모두 seed=7, PCAP on, workers=1이다. DB는 네트워크가 없는 임시
컨테이너와 Unix socket을 사용했고 컨테이너 예산은 CPU 1코어·RAM 256MiB다.
애플리케이션은 Python 3.13.13에서 실행했다. 준비·drain의 CPU와 준비 단계의
RSS가 포함되며 PostgreSQL CPU·RSS는 표의 프로세스 수치에 포함하지 않았다.
코드는 ec8436e 위 작업 중 상태였다.

입력 종류·pps가 다른 두 실행의 CPU/RSS 차이를 개선 효과로 해석하지 않는다.
일반 입력에서도 cold-start 엔진 경보가 나올 수 있으며, 저장 이벤트 수는
정상·공격 판정 정확도를 뜻하지 않는다. 커널·링크 손실과 정확한 지연 p99는
미측정이다. 30분·10분 장기 기준선과 HDD 지원 목표를 대신하지 않는다.
