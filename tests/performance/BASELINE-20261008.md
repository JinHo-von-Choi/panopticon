# 2026-10-08 반복 폭풍과 이벤트 루프 양보 재현

격리 PostgreSQL 16·합성 입력·PCAP on·workers=1에서 10초간 반복 경보 10,000건을
주입했다. 운영 DB·NIC·방화벽·외부 채널을 사용하지 않았다. DB 컨테이너는
네트워크 없이 CPU 1코어/RAM 256MiB이며 앱의 CPU 제한과 전용 하드웨어는 없다.

시간 분할은 패킷 한 건을 중단하지 않는다. 최대 500개를 연속 처리하던 버퍼가
10ms 이후 다음 패킷부터 제어를 양보해 타이머·주입·저장 태스크가 실행될 기회를
얻는다. 이후 실행에서는 모든 주입 경보가 집계됐고 결과 큐 app drop은 없었다.

두 실행 모두 요청 1,000pps를 생성하지 못했다. CPU·생성 패킷·전체 이벤트 수의
차이는 동일 실입력 비교가 아니며 처리량 개선율로 해석하지 않는다. 30분/10분
부하, 지연 p99, HDD I/O 감소, 커널/링크 손실 목표는 아직 미검증이다.

두 보고서의 revision은 e83cae0이다. 후자는 그 revision 위의 capture 시간 분할
변경이 포함된 dirty 작업 트리였고, 기존 사용자 .gitignore 변경도 있었다.
