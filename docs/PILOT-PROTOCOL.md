# 도입 평가

Panopticon이 조사 시간을 줄이는지, 운영 중에 안정적인지 실제 환경에서 확인하는 절차입니다. 기존 Suricata에 EVE 콘솔을 붙여 진행합니다.

```mermaid
flowchart LR
    P[준비<br/>범위·기간 승인] --> I[설치<br/>첫 사건까지 시간]
    I --> C[업무 맥락 등록]
    C --> X[교차 조사<br/>기존 도구 vs Panopticon]
    X --> O[30일 이상 운영 기록]
    O --> R[결과 보고]
```

## 준비

- 관리자 승인을 받고 관측 구간, 기간, 자료 보존 범위를 정합니다.
- 버전, IDS 룰셋, 장치 수, 입력 로그, 앱·IDS·DB 자원을 기록합니다.
- SPAN 센서가 실제로 보는 구간을 확인합니다.
- 운영망에서의 공격 실험과 차단 시험은 따로 승인받습니다.
- 기간은 시작 전에 정합니다. 30일 이상, 백업 주기와 업무 외 시간을 포함합니다. 설치·접속 실패나 중단 기간도 결과에 남깁니다.

## 평가 순서

1. 설치 가이드만 보고 연결해, 첫 사건을 볼 때까지 걸린 시간을 잽니다.
2. 장치 역할, 담당자, 업무 시간, 기대 통신을 등록합니다. 경보 원문과 담당자의 판정(정상·공격·미확정)을 구분해 둡니다.
3. 같은 사건을 기존 도구와 Panopticon에서 번갈아 조사해 시간을 비교합니다. 순서를 바꿔 가며 익숙해지는 효과를 줄입니다.
4. 경보·대표 사건·검토 사건 수, 수집 지연, 누락 가능성, 저장 실패, 재시작과 복구 시간을 기록합니다.
5. 근거가 갖춰진 설정 후보만 승인합니다. 공격 샘플을 놓칠 위험이 있는 후보는 제외하고, 원복 결과도 남깁니다.

## 기록 항목

| 항목 | 기록할 것 |
| --- | --- |
| 운영 부담 | 설치 시간, 주간 검토·관리 시간, 지원이 필요했던 작업 |
| 조사 효율 | 같은 사건의 조사 시간 중앙값, 인계·재조사 시간 |
| 경보 품질 | 원경보·대표 사건·검토 사건 수, 판정 근거 |
| 안정성 | 입력·저장량, 지연, 누락 가능성, 중단·재시작·복구 |
| 자원 사용 | 앱·IDS·DB 각각의 CPU, 메모리, 디스크, I/O |

해석 규칙:

- 경보를 묶어 사건 수가 줄어든 것은 오탐 감소가 아닙니다.
- 오탐 비율은 실제로 검토한 사건만으로 계산하고, 표본 추출 방법과 미확정 수를 함께 밝힙니다.
- 탐지율은 30일 운영 수치로 낼 수 없습니다. 정답셋과 공격 수를 통제한 별도 시험에서 측정합니다.

## 결과 공유

환경, 기간, 버전, 입력량, 관측하지 못한 범위, 조사 시간, 운영 부담, 실패하거나 측정하지 못한 항목을 함께 보고합니다. 단위 시험 수치를 NIC 처리량으로 해석하거나 시험 조건 밖으로 넓혀 말하지 않습니다.

외부에는 승인된 집계 자료만 공유합니다. 원본 주소, 패킷, 로그, 토큰, 개인정보, 내부 접속 정보는 지웁니다.
