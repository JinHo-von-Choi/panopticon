# 소규모 LAN 파일럿 검증 절차

이 문서는 현장 검증의 실행안이다. 참가자 모집·연락·배포·데이터 반출은 아직
실행하지 않았다. 설치 점검의 통과나 합성 replay 결과를 현장 성능으로 표시하지 않는다.

## 대상과 사전 기록

서로 다른 소규모 LAN 세 곳에서 현장 담당자의 동의를 받아 14일간 진행한다.
NAS/백업 중심 환경, DB/업무 서버 환경, 프린터/일반 PC 환경을 포함한다.
망 규모와 센서 위치가 다르면 결과를 합산하지 않고 환경별로 제시한다.

각 현장에 아래 항목을 기록한다.

- 담당자와 기간, 설치 시작 시각, Git revision·설정/피드 버전.
- CPU·RAM·디스크 종류, 워커 수, DB 위치, 컨테이너·서비스 메모리 상한.
- 감시 인터페이스, SPAN의 원본 포트/방향과 알려진 미관측 구역, NetFlow exporter.
- 관리 접근 경로·인증·TLS 구성, 설정 writable 여부, 증거 보존 예산.
- 수동 확인한 자산의 MAC/IP·역할·확인 근거·만료. 공유 IP와 자동 추정은 별도 표시.
- 기존 모니터와 비교할 경우 동일 하드웨어·입력·엔진 범위 및 기능 차이.

설치 점검 화면은 시작점이다. SPAN coverage와 전체 서비스 메모리는 unknown이므로
담당자가 승인된 통신 한 쌍의 실제 발생과 관측을 대조한다. 테스트가 안 보이면
범위를 수정하고 미관측을 기록한다. 평소 트래픽 0만으로 설치 성공/실패를 결정하지 않는다.

## 14일 진행

1. **0일:** 설치부터 첫 유효 자산 지도까지 걸린 시간과 실패·재시도를 기록한다.
   목표는 30분 이내다. IP/MAC과 최소 한 통신 관계를 실제로 대조해야 유효로 인정한다.
   설치 지원 시간이 필요하면 관리자 시간과 지원자 시간을 따로 센다.
2. **1~6일:** 기본 설정으로 관측한다. 정상 백업·DB·VM 작업의 시작/종료와
   담당자 레이블을 기록한다. 통계 학습이 정상 업무 레이블을 대신하지 않는다.
   미확인 경보를 임의로 false positive에 포함하지 않는다.
3. **7일:** 담당자와 경보·관계 변화·관측 누락을 검토한다. 전역 IP whitelist로
   경보를 지우지 않는다. 변경 후보는 이전/새 버전·범위·만료·복구 절차를 기록하고,
   같은 정상/공격 입력을 격리 replay로 비교한다. 지원 밖 엔진은 비교 불가로 남긴다.
4. **8~14일:** 현장에서 승인된 후보만 적용한다. 변경 전후에 같은 업무 시간대를
   비교한다. 운영 검토 시간을 매일 기록하고 주간 합계를 계산한다. 목표는 주 30분 이하다.
5. **14일:** 실패와 미측정을 포함해 환경별 결과를 확정한다. 참가자가 반출을
   승인한 익명 집계만 공개 대상으로 만든다. 원본 패킷·주소·토큰은 공개 결과에 넣지 않는다.

## 입력과 결과의 단위

같은 Git revision·설정·피드·정규화 버전과 동일 입력 해시를 묶는다.
정상 시나리오와 공격 시나리오는 독립 실행한다. replay의 arp_spoof·port_scan·
data_exfil 특징값 계약 밖 엔진을 재현 성공으로 보고하지 않는다. 독립 엔진의 회귀
시험은 별도 증거이며 현장 탐지 성공과 동일하게 취급하지 않는다.

경보 수는 원본 관측, 저장된 대표, 집계 count, 원격 알림을 나눠 기록한다.
집계가 경보를 줄인 것을 탐지 자체가 사라진 것으로 계산하지 않는다.
app drop·kernel drop·억제·만료 미확정 저장은 단계와 시간창별로 따로 기록한다.
분모가 다르거나 측정할 수 없는 NIC/스위치 손실은 합산하지 않는다.

| 실행마다 기록할 값 | 해석 |
| --- | --- |
| 입력 수·실제 pps·입력 해시·시간창 | 요청 pps와 실제 생성 pps를 구분 |
| 정상 레이블의 불필요 대표 경보 | 변경 전후 같은 업무/관측 범위에서 비교 |
| 공격 시나리오별 검출·지연 | 이전 검출 성공 사례 하나라도 잃으면 후보 거부 |
| 확정 저장 ID·집계 count·미확정 손실 | 저장 응답 유실을 성공/실패로 추정하지 않음 |
| 주/워커/DB CPU·RSS·전체 메모리 상한 | 주 프로세스 RSS만으로 전체 예산 통과를 선언하지 않음 |
| 실제 DB/PCAP 쓰기 byte·IOPS·지연 | 메모리 계수나 파일 수만으로 HDD 부하 감소를 주장하지 않음 |
| 담당자 설치·검토·복구 시간 | 개발자 지원이 없을 때의 운용 가능성 평가 |

정상 백업·DB·VM의 불필요 대표 경보 70% 감소는 목표다. 이전 값이 0이면 감소율을
계산하지 않는다. 입력·업무 시각·관측 범위가 다른 비교는 비교 불가로 남긴다.
입력 발생부터 저장/표시까지 지연을 기록하며 drop과 미확정 저장을 지연 표본에서
제외한 경우 제외 수를 같이 표시한다.

## 변경 승인 기록과 실패 처리

변경 기록에는 후보 ID, 이전/새 설정, 자산/peer/서비스/시간/volume 범위,
확인자·만료·replay run ID, 비교 불가 사유, 업무 영향과 rollback을 포함한다.
읽기 전용 설정이나 버전 충돌은 변경 실패로 기록한다. 저장 실패를 화면 성공으로
처리하지 않는다. 공격 검출 손실·미확정 저장 증가·업무 지연이 확인되면 해당 후보를
되돌리고 원인 및 재현 입력을 기록한다. 확인되지 않은 값을 완료로 채우지 않는다.

SPAN 센서의 input 방화벽은 다른 호스트 사이 통신을 막는다는 근거가 아니다.
파일럿에서 대응 효과를 시험할 경우 실제 경로·권한·복구 가능성을 먼저 확인하고,
관측-only와 실제 enforcement 결과를 구분한다. 운영 차단 실험은 이 문서 작성만으로
승인된 것으로 취급하지 않는다.

## 결과 양식

현장별 보고는 환경·기간·버전, 검증한 관측 범위, 설치 시간, 정상/공격 비교,
자원·I/O, 주간 검토 시간, 실패·미측정·비교 불가, 후보 적용/rollback 기록을 포함한다.
동의된 공개 집계와 내부 원자료를 구분한다. 세 현장 모두의 결과가 확정되기 전에는
차별화 효과나 현장 목표 달성을 제품 문구로 확정하지 않는다.
