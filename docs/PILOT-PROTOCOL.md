# 도입 평가

Panopticon이 사건 조사 시간을 줄이고 안정적으로 돌아가는지 직접 운영 환경에서 점검하는 절차입니다. 기본 평가는 기존 Suricata에 읽기 전용 EVE 콘솔을 연결해 진행합니다.

## 준비

먼저 관리자 승인을 얻고 관측 구간, 기간, 자료 보존 범위를 확정합니다. 버전, IDS 룰셋, 장치 수, 입력 로그뿐만 아니라 앱·IDS·DB가 쓰는 자원도 빠짐없이 기록해 둡니다. SPAN 센서가 실제로 들여다보는 구간 역시 함께 확인합니다. 운영망에서 수행할 공격 실험과 차단 시험은 별도로 승인을 받습니다.

평가 기간은 착수 전에 확정해야 합니다. 30일 이상 운영하면서 전체 백업 주기와 비업무 시간대를 반드시 포함하도록 일정을 잡습니다. 도중에 발생한 설치·접속 실패나 작업 중단 기간도 결과에 고스란히 남깁니다.

## 평가 순서

1. 설치 안내만 참고해 연결을 마치고 첫 사건을 확인할 때까지 걸린 시간을 기록합니다.
2. 장치 역할, 담당자, 정상 업무 시간, 기대 통신을 등록합니다. 경보 원문과 담당자의 정상·공격·미확정 판정을 명확히 구분합니다.
3. 동일한 사건 자료를 기존 도구와 Panopticon 양쪽에서 번갈아 가며 조사해 소요 시간을 비교합니다. 순서를 교차 검증해 작업자가 시스템에 익숙해져서 생기는 왜곡을 줄입니다.
4. 운영 중에 발생한 경보·대표 사건·검토 사건 수, 수집 지연·누락 가능성, 저장 실패, 시스템 재시작과 복구에 소요된 시간을 꼼꼼히 적어 둡니다.
5. 설정 변경은 타당한 근거가 갖춰진 후보만 승인합니다. 공격 샘플이 유실될 위험이 있는 후보는 배제하며, 설정을 원복했을 때의 결과도 남깁니다.

## 판정에 사용할 기록

| 항목 | 기록 방법 |
| --- | --- |
| 운영 부담 | 설치 시간, 주간 검토·관리 시간, 지원이 필요했던 작업 |
| 조사 효율 | 같은 사건의 조사 시간 중앙값, 인계·재조사에 걸린 시간 |
| 경보 품질 | 원경보·대표 사건·검토 사건 수와 판정 근거 |
| 안정성 | 입력·확정 저장량, 지연, 누락 가능성, 중단·재시작·복구 |
| 자원 사용 | 앱·IDS·DB 각각의 CPU·메모리·디스크·I/O |

단순 경보 집계로 겉보기에 사건 수가 줄었다고 해서 이를 오탐 감소로 계산해서는 안 됩니다. 오탐 비율은 실제 검토를 마친 사건에 한해서만 산출하고, 표본을 뽑은 방식과 미확정 사건 수도 숨김없이 밝힙니다. 30일 동안 관측한 수치만으로는 탐지율을 온전히 도출할 수 없습니다. 탐지율은 정답셋과 전체 공격 수가 통제된 별도 승인 시험에서만 정확히 측정합니다.

## 결과 공유

점검 환경, 평가 기간, 버전, 입력량과 더불어 관측에서 누락된 범위, 조사 시간, 운영 부담, 실패하거나 측정하지 못한 항목까지 함께 투명하게 보고서에 담습니다. 단위 기능 시험 수치와 실제 NIC 처리량을 혼동하지 않아야 하며, 시험 조건 밖의 영역으로 성능 지표를 과장해 해석하지 않습니다.

외부에 공유할 때는 사전 승인을 거친 집계 자료만 전달합니다. 원본 주소·패킷·로그·토큰·개인정보와 내부 접속 정보는 반드시 지워야 합니다.
