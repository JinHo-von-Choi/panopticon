# 도입 평가

이 가이드는 Panopticon이 자신의 네트워크에서 필요한 통신을 관측하고, 담당자가 조사할 사건을 찾는 데 도움이 되는지 평가하는 방법입니다. 제품의 일반적인 성능 보증이 아니라 개별 도입 판단에 사용합니다.

## 시작 전에 정할 사항

관리자의 승인을 받고 관측 구간과 기간, 자료 보존·반출 범위를 정합니다. 장치 수와 주요 서비스, SPAN 또는 NetFlow 수집 위치, 센서·DB·저장 장치를 기록합니다. 운영망의 공격 실험과 차단 시험은 일반 관측과 별도로 승인받습니다.

## 평가 순서

1. **설치:** 담당자가 가이드만으로 설치하고 필요한 장치와 통신을 확인하는 데 걸린 시간을 기록합니다.
2. **업무 관측:** 백업·DB·VM 등의 정상 작업 시간과 반복 경보를 기록합니다. 담당자가 확인한 장치 역할과 기대 통신을 등록합니다.
3. **설정 비교:** 정상·공격 샘플을 따로 준비하고 변경 전후 관측을 비교합니다. 이전에 관측한 공격을 잃는 후보는 적용하지 않습니다.
4. **운영:** 승인한 후보만 적용하고 비슷한 업무 시간대의 경보, 저장 장애, 조사 소요 시간을 비교합니다.
5. **결과:** 개선과 실패, 관측하지 못한 범위와 추가 지원이 필요했던 작업을 함께 정리합니다.

최소 한 번의 전체 백업 주기와 평일·비업무 시간대를 포함하세요. 14일처럼 기간을 미리 정하면 조건을 바꿔 유리한 결과만 선택하는 일을 피할 수 있습니다.

## 비교할 항목

| 항목 | 기록 방법 |
| --- | --- |
| 관측 범위 | 확인한 구간과 보이지 않는 구간 |
| 정상 업무 경보 | 대표 사건 수와 반복 발생 횟수 |
| 공격 샘플 | 변경 전후 관측 유무와 지연 |
| 저장과 근거 | 확정 저장, 증거 파일, 실패·미확정 수 |
| 자원 사용 | 센서와 DB의 CPU·메모리·디스크 사용 |
| 담당자 작업 | 설치·검토·복구에 걸린 시간 |

서로 다른 입력량·관측 범위·업무 시간대의 결과를 직접 비교하지 않습니다. 재현 입력은 버전·설정·분류와 함께 보관합니다. 샘플 비교는 해당 특징값에 대한 결과이므로 모든 공격의 탐지 성능으로 해석하지 마세요.

## 결과 기록

환경·기간·버전, 설치와 관측 범위, 변경한 설정, 정상·공격 비교, 자원 사용, 담당자 작업 시간, 실패·미측정 항목을 기록합니다. 적용한 후보의 승인 근거와 되돌림 여부도 포함합니다.

외부에 공유할 때는 승인된 집계만 사용하고 원본 주소·패킷·토큰·개인정보를 제거합니다.
