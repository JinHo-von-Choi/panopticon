# Suricata EVE 연결

기존 Suricata가 생성한 경보를 Panopticon에서 분석할 때 사용하는 연동 방식입니다. Suricata가 패킷을 분석하면 Panopticon이 해당 EVE 로그를 읽어 들여 사건 목록과 실시간 콘솔에 경보를 띄웁니다. 외부 IDS 설정이나 방화벽 규칙은 건드리지 않습니다.

## 연결하기

Suricata에서 한 줄마다 JSON 객체 하나씩 기록하도록 `eve.json` 출력을 미리 구성합니다. 권한 확인이 필요합니다. Panopticon 실행 계정에는 로그 디렉터리 탐색 권한과 파일 읽기 권한만 있으면 충분하며 패킷 캡처 권한이나 root 권한까지 넘겨줄 필요는 없습니다.

설정 파일에는 로그 경로와 입력 식별자를 지정합니다.

```yaml
netwatcher:
  input:
    mode: eve
    eve:
      sources:
      - sensor_id: suricata-1
        source_id: office-eve
        directory: /var/log/suricata
        filename: eve.json
  web:
    host: 127.0.0.1
    port: 38585
```

DB 접속과 계정 인증 절차는 [설정 가이드](CONFIGURATION.md)를 따릅니다. 외부 네트워크 인터페이스로 콘솔을 열어둘 때는 반드시 인증을 켜 두어야 합니다. 위의 예시는 로컬 루프백 접속만 열어 둔 구성입니다.

```bash
python -m alembic upgrade head
python -m netwatcher -c config/default.yaml
```

프로세스를 실행한 뒤에는 콘솔의 **관측 범위** 화면으로 이동해 입력별 수집 상태와 사건 목록에 실제 Suricata 경보가 들어오는지 점검합니다. `/ready` 엔드포인트는 DB와 파일 수집 준비를 마치면 200 응답을 반환하지만, 이 응답 코드가 네트워크 전체를 누락 없이 감시하고 있다는 상태까지 보증하지는 않습니다.

입력 소스는 최대 8개까지 지정할 수 있습니다. 식별 규칙을 지켜야 합니다. `sensor_id`와 `source_id`의 조합은 입력마다 서로 달라야 하고 서비스 재시작 후에도 유지되어야 하며 영문·숫자·밑줄·마침표·하이픈만 사용해 각각 64자 이내로 입력합니다. 파일 이름 자리에 디렉터리 경로를 섞어서는 안 됩니다. 심볼릭 링크나 일반 파일이 아닌 입력은 모두 거절합니다.

### Docker Compose

`.env` 파일에 DB 접속 정보와 로그인 자격증명, JWT 값을 지정하고 컨테이너 환경에서 함께 구동하는 내부 DB 주소는 `NETWATCHER_DB_HOST=db`로 적습니다. 로그 볼륨 바인딩은 다음 두 환경변수로 설정합니다.

```dotenv
PANOPTICON_EVE_DIR=/var/log/suricata
PANOPTICON_EVE_GID=10001
```

`PANOPTICON_EVE_GID`에 적힌 예시값을 그대로 두지 말고 호스트에서 해당 로그를 읽을 수 있는 실제 GID로 변경해야 합니다. 호스트 디렉터리가 이미 존재하고 지정한 그룹에 디렉터리 실행(탐색) 권한과 로그 파일 읽기 권한이 부여되어 있어야 컨테이너가 정상 작동합니다. 컨테이너 내부에는 지정 경로를 `/var/log/suricata` 위치로 읽기 전용 마운트합니다.

```bash
docker compose --profile db up -d db
docker compose --profile db --profile migrate run --rm db-migrate
docker compose --profile db up -d netwatcher
```

콘솔 포트는 호스트의 `127.0.0.1:38585`로 바인딩됩니다. 컨테이너 간 통신이 도커 브리지 네트워크를 거치므로 로그인 인증 설정을 빠뜨리지 말아야 합니다. 호스트 외부의 별도 DB를 연결할 때는 컨테이너 네트워크에서 직접 접근 가능한 주소를 적어야 하며 호스트 루프백인 `127.0.0.1`을 적으면 연결이 끊어집니다.

자체 패킷 캡처까지 묶어서 띄우려면 [설치 안내](INSTALL.md)의 Native 설정 생성 절차에 맞춰 콘솔과 센서 구성을 함께 준비합니다. 생성한 환경변수 파일과 추가 Compose 매니페스트를 전달해 두 컨테이너를 함께 실행합니다.

```bash
docker compose --env-file installation-native/.env -f docker-compose.yml -f docker-compose.native.yml --profile db up -d --build netwatcher native-sensor
```

### systemd

`deploy/panopticon-eve.service` 파일은 비특권 일반 계정으로 프로세스를 실행하는 서비스 템플릿입니다. 소스 트리와 파이썬 가상 환경 위치, 설정 및 환경변수 경로를 먼저 확인합니다. 기본 설정값은 `/opt/panopticon`, `/etc/panopticon/config.yaml`, `/etc/panopticon/panopticon.env`입니다. 전용 실행 계정인 `panopticon`이 설정 파일과 EVE 로그 파일을 읽을 수 있어야 하므로 필요하다면 서비스 유닛의 보조 그룹에 해당 로그 읽기 그룹을 추가합니다.

서비스는 패킷 로우 소켓 생성을 차단하며 디스크 쓰기 범위도 `/var/lib/panopticon` 하나로 제한합니다. 로그 캐시와 설정 캐시를 해당 경로 안에서만 관리하므로 일반 사용자 홈 디렉터리는 건드리지 않습니다. 접속 설정은 명시된 환경변수 파일과 설정 파일에서만 불러오며 작업 디렉터리에 놓인 `.env` 파일을 임의로 읽어 들이지 않습니다.

자원 제한도 명시되어 있습니다. 기본 메모리 상한은 512MiB이고 CPU 사용 상한은 1개 코어 분량입니다. 메모리가 384MiB에 도달하면 메모리 회수 압력이 발생하고 상한선에 도달하면 프로세스가 강제 종료될 수 있습니다. 유닛에 `Restart=on-failure`가 지정되어 있어 비정상 종료 시 곧바로 다시 실행되며 DB에 기록된 마지막 수집 오프셋을 읽어 작업을 재개합니다. DB 서버나 Suricata 엔진 리소스는 이 제한 계산에 포함되지 않습니다. 운영 환경의 트래픽과 하드웨어 규격에 맞춰 서비스 유닛의 `MemoryHigh`, `MemoryMax`, `CPUQuota` 수치를 조절합니다.

템플릿 등록과 서비스 기동은 시스템 설치 담당자가 진행합니다.

## 장치 역할과 경보 근거 확인

사건 상세 화면의 **원본 EVE 로그 근거** 항목에서 센서 식별자, 입력 소스, Suricata 규칙 ID, 원래 심각도, 플로우 ID, 원본 라인 오프셋을 확인합니다. 전체 로그 원문이 필요하면 별도로 보관해 둔 Suricata 원본 저장소에서 확인해야 합니다.

장치 역할은 사전에 등록한 IP와 MAC 주소가 경보 상의 네트워크 주소와 일치하면서 관리자 승인 상태가 유효하게 유지될 때만 화면에 표시합니다. IP 주소 하나만 기록된 경보에는 역할을 임의로 매핑하지 않습니다. MAC 주소가 일치하지 않거나 공용 IP를 사용하거나 관리자 승인 기한이 지났거나 주소가 변경된 상태라면 검증을 다시 거쳐야 합니다. 장치 역할이 확정되었다고 해서 Suricata가 생성한 경보나 심각도 수치를 임의로 낮추지는 않습니다.

Suricata의 EVE 설정에서 `ethernet: yes` 옵션을 켜 두어야 이벤트 로그에 MAC 주소가 기록됩니다. Panopticon은 로그에 기록된 주소 데이터를 가공 없이 담아둘 뿐 비어 있는 주소를 임의로 채워 넣지 않습니다. 게이트웨이나 라우터를 거친 통신 패킷은 이더넷 프레임 주소가 출발지 장비의 실제 MAC과 다를 수 있습니다. 세부 사항은 [Suricata EVE 출력 설정](https://docs.suricata.io/en/latest/output/eve/eve-json-output.html)을 참조합니다.

## 기록과 복구

수집 대상 이벤트는 `alert`, `flow`, `dns`, `tls`입니다. 원본 규칙 ID와 심각도는 누락 없이 유지합니다. 사건 화면에서는 Suricata 심각도 1·2·3을 각각 `CRITICAL`·`WARNING`·`INFO` 라벨로 매핑하여 표시합니다.

전체 로그 텍스트를 통째로 DB에 저장하지는 않습니다. 파일 세대, 바이트 단위 오프셋, 해시값을 남겨 원본을 역추적할 수 있게 유지하고 분석에 필수적인 속성만 선별해 저장합니다. DNS 질의 이름이나 TLS SNI·인증서 주체, HTTP 본문과 헤더는 기본 수집 스키마에서 제외됩니다. 다른 유형의 이벤트 역시 역참조 오프셋만 남겨둘 뿐 사건 목록용 경보 레코드로 변환하지 않습니다. 상세 원본 데이터가 필요한 분석 작업이 있다면 원본 Suricata 로그 파일을 삭제하지 말고 별도로 보관해야 합니다.

로그 기록, 경보 생성, 파일 오프셋 전진 처리는 단일 트랜잭션으로 묶여 실행됩니다. DB 저장이 실패하면 파일 포인터도 진행되지 않으며 DB 응답만 유실된 상황에서도 마지막 커밋 포인터를 다시 조회하므로 경보가 중복 생성되지 않습니다. 쓰기 도중 끊긴 불완전한 JSON 라인은 줄바꿈 문자가 들어올 때까지 버퍼에서 대기합니다.

로그 로테이션이 발생하면 이전 로그 파일을 끝까지 읽어 들이는 작업부터 완료합니다. 프로세스를 재시작할 때도 디렉터리에 남아 있는 직전 세대 파일부터 탐색합니다. 이전 파일이 디스크에서 이미 삭제되었거나 파일이 잘려 나간 흔적이 발견되면 데이터 누락 가능성을 메타데이터에 기록합니다. 로테이션 직후 발생하는 지연 쓰기는 기본 2초 동안 기다리지만 이 유예 시간을 초과해 밀려드는 지연 기록까지 완전히 보장하지는 못합니다. 파일 시스템에서 감지할 수 없는 잘림이나 덮어쓰기, Suricata 앞단에서 발생한 패킷 드롭 가능성도 상존하므로 100% 무손실 수집을 보장하지는 못합니다.

## 수집에 문제가 있을 때

파이프라인 상태를 확인할 때는 **운영 상태** 메뉴에서 소스별 수집 현황, 수집 대기량, 누락 징후, 거절된 레코드 수, 보존 공간 한도를 점검합니다. 수집 대기량은 현재 읽고 있는 파일에서 아직 DB에 저장하지 않은 바이트 수입니다. 다른 회전 파일의 대기량이나 Suricata의 패킷 손실은 포함하지 않습니다. 파일 상태를 확인할 수 없으면 0 대신 **확인 불가**로 표시합니다. EVE 수집 모드로 동작할 때는 인라인 패킷 캡처 엔진과 트래픽 차단 메뉴가 UI에 나타나지 않습니다.

기본 데이터 보존 기한은 수신 시점을 기준으로 30일이며 입력 소스 1개당 레코드 25만 개와 본문 용량 256MiB를 상한선으로 둡니다. 경보에 딸려 들어간 사건 복사본까지 포함하는 본문 용량 기준이며 운영자가 기록한 업무 판정이나 인계 이력은 이 용량 제한과 무관하게 보관됩니다. DB 테이블, 인덱스, WAL 파일이 디스크를 실제로 차지하는 용량은 서버에서 별도로 모니터링해야 합니다. 수집 파라미터는 설정 파일에서 수정합니다.

```yaml
netwatcher:
  input:
    eve:
      retention:
        days: 30
        max_records: 250000
        max_bytes: 268435456
        cleanup_interval_seconds: 60
```

보존 한도를 초과한 배치 데이터는 DB에 쓰지 않고 현재 읽기 오프셋을 그대로 유지합니다. 설정 기한이 지난 오래된 EVE 레코드와 연결된 사건들을 먼저 삭제해 용량을 확보한 뒤에야 멈췄던 수집을 재개합니다. 한 차례 정리 작업마다 소스별로 최대 1,000개씩 삭제합니다. 감사나 분석 목적으로 장기 데이터가 필요하다면 원본 파일과 DB 덤프를 별도 백업 장치에 따로 저장해야 합니다.

- **수집 확인 필요:** 파일 경로, 권한 설정, DB 커넥션을 점검합니다. 수집 파이프라인이 멈춘 사이에 Suricata 로테이션으로 원본 로그가 디스크에서 먼저 삭제되지 않도록 파일 보존 일수를 확인합니다.
- **수집 대기량 증가:** 대기량이 배치 바이트 상한의 두 배를 초과한 상태입니다. DB 응답 시간과 보존 한도를 확인하고 대기량이 줄어드는지 관찰합니다. 대기량만으로 데이터 유실 여부를 단정하지는 않습니다.
- **수집 상태 점검 필요:** 로그 회전 시점의 파일 잘림, 깨진 JSON 라인, 파일 상태 조회 실패를 점검합니다. 입력 라인 하나가 256KiB를 초과하면 본문 저장을 거부하고 거절 카운트만 증가시킵니다.
- **회전 디렉터리 탐색 상한:** 한 디렉터리에서 탐색하는 파일 수는 최대 128개로 제한됩니다. 회전된 로그가 많이 쌓였다면 별도 아카이브 디렉터리로 이동시켜 두어야 새 파일을 제때 탐색할 수 있습니다.
- **저장 한도 도달:** 관측 범위 메뉴에서 보존된 레코드 수와 사용량을 확인하고 보존 일수나 용량 한도를 늘립니다. 큐에 밀려 있는 원본 파일이 로테이션으로 삭제되면 제거된 데이터를 복구할 방법은 없습니다.

EVE 모드로 동작할 때는 패킷 직접 캡처, NetFlow 병행 수집, 이중화(HA), OS 방화벽 차단 기능이 활성화되지 않습니다. 인터페이스에서 패킷을 직접 받아내야 한다면 `input.mode: native`로 전환합니다.
