# 기여 기준

기능을 추가하거나 바꿀 때 지켜야 할 제품 동작입니다. 개발 환경과 명령은 [개발 가이드](DEVELOPMENT.md)에 있습니다.

## 원칙

| 원칙 | 뜻 |
| --- | --- |
| 거절이 경고보다 낫다 | 잘못된 설정·입력은 기록만 하고 진행하지 않고 거절한다 |
| 감사가 먼저다 | 설정을 바꾸는 요청은 감사 기록을 남기지 못하면 실패한다 |
| 조용히 나빠지지 않는다 | 구성요소가 동작하지 않으면 정상으로 보고하지 않고 그 상태를 화면에 드러낸다 |
| 미확정은 성공이 아니다 | 결과를 확인하지 못한 저장·전달·차단은 성공으로 처리하지 않는다 |

## 탐지와 관측

- 관측 범위와 입력 누락을 항상 함께 보여 줍니다. 경보가 없다는 이유로 구간 전체를 안전하다고 안내하지 않습니다.
- 누락률은 같은 단계, 같은 시간대의 수신 수로 계산합니다. 앱·커널·네트워크 장비의 누락을 합치지 않습니다.
- 정상 업무 경보의 심각도를 낮출 때는 장치 소유 관계, 상대, 서비스, 시각, 전송량을 모두 확인합니다. 확인할 수 없거나 만료된 조건에는 적용하지 않습니다.
- 공격 입력이 정상 기준선에 학습되지 않는지 상태값과 회귀 시험으로 확인합니다.

## 변경과 승인

- AI와 분석 역할은 설명과 제안만 합니다. 설정 쓰기와 승인은 관리자 권한이 필요합니다.
- API의 권한 검사는 실제 변경 경로와 일치해야 합니다. 변경 라우트를 추가하면 `require_role(Role.ADMIN)`을 선언하고 `create_app`에 등록합니다. 누락은 출시 검사 G0-14가 잡습니다.
- 설정 후보에는 기준값과 비교 결과를 연결합니다. 현재 설정이 바뀌었거나 공격 관측을 놓치는 후보는 반영하지 않습니다.
- 파일 저장이나 엔진 재생성에 실패하면 이전 설정과 엔진 상태를 유지하고 실패로 응답합니다.

## 저장과 외부 효과

- DB 저장, 패킷 파일 생성, 알림 전달, OS 차단은 각각 결과를 확인합니다.
- 재시도하는 저장 작업은 고유 식별자로 중복을 막습니다.
- 원격 전달과 방화벽 조치는 응답이 끊겼을 때 같은 작업이 두 번 실행되면 어떻게 되는지 미리 정합니다.
- 대기열, 메모리, 파일, 처리 시간에는 상한을 둡니다.

## 방화벽과 권한

- 차단은 실제 트래픽 경로를 통제하는 위치에서만 효과를 검증합니다. 미러링 센서의 로컬 방화벽으로 네트워크가 차단됐다고 설명하지 않습니다.
- 차단 전에 대상, 관리 경로 영향, 만료, 복구 방법을 확인합니다.
- 외부 입력을 셸 명령으로 넘기지 않습니다.
- 지원하지 않는 백엔드나 권한 구성을 지원 기능처럼 문서에 쓰지 않습니다.

## UI

- 요청 중, 적용 완료, 실패, 확인 불가를 화면에서 구분합니다.
- 화면을 갱신해도 사용자가 고른 필터, 선택 항목, 초점이 유지돼야 합니다.
- 중요한 상태는 색만으로 나타내지 않고 글자를 함께 씁니다.
- 대시보드는 기존 ES 모듈 구조와 한국어·영어 번역 파일(`static/locales/{ko,en}`)을 따릅니다.

## 문서

- 독자가 할 일과 확인할 결과를 중심으로 씁니다.
- 기능 설명은 현재 코드 동작과 일치해야 합니다.
- 개인 경로, 비공개 접속 정보, 개발 일지, 실행 로그를 넣지 않습니다.
- 사용법이 바뀌면 관련 가이드와 [릴리스 노트](../CHANGELOG.md)를 함께 고칩니다.

## 검증

- 변경과 관련된 단위 시험, 마이그레이션 확인, 출시 검사를 실행합니다.
- 건너뛴 시험과 실제 장비가 필요한 시험은 따로 적습니다.
- 한 장비에서 짧게 돌린 합성 시험 결과를 일반 성능 보증으로 쓰지 않습니다.
