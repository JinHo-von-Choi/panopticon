# 거버넌스 — 이 변경이 왜 이렇게 생겼는가

작성일: 2026-10-06
대상: 이 저장소를 바꾸는 사람

## 원칙 1. 비활성화는 결함 수정 완료가 아니다

기능을 끄면 경보가 멈추고, 경보가 멈추면 아무 문제가 없어 보인다.
그래서 **꺼진 것과 고쳐진 것을 구분할 장치**를 먼저 만든다.

- 지원 프로필 계약 (`netwatcher/support.py`) — 어떤 조합이 지원되는지
- 관측 범위 (`netwatcher/observability/observation.py`) — 무엇을 보고 있는지
- 게이트 (`scripts/gates.py`) — 이 상태로 배포해도 되는지

## 원칙 2. 게이트는 배포 가능성을 판정한다

게이트는 "맞았는지" 를 검사하지 않는다. **"이 상태로 배포해도 되는가"** 를
검사한다. 그래서 통과로 오인될 수 있는 항목을 넣지 않는다.

```
[FAIL] G0-1 지원 프로필 계약
       [SUP-020] web.host: 인증이 비활성화된 상태로 '0.0.0.0' 에 바인드된다
```

이 판정 하나가 실제 노출 위험 하나를 막는다.

## 원칙 3. 계약을 통과했다 고 enforcement 통과라고 말하지 않는다

이 문장을 화면에도, API 응답에도, 로그에도 넣었다. 이게 빠지면 대시보드는
그 자체로 검증 위장이 된다.

- `governance.js` — "운영 검증을 통과했다는 뜻이 아니다"
- `executor_capabilities()` — `applies_to_os: false` 를 그대로 노출
- `SupportContract.enforce` 로그 — 거부 사유를 남김

## 원칙 4. 없는 지표를 만들지 않는다

측정할 수 없는 것은 `unknown` 이라고 말한다.

| 측정 가능 | 측정 불가 → `unknown` |
|-|-|
| 앱 drop (같은 단계·같은 시간창의 분모) | NIC/스위치 링크 손실 |
| 커널 drop (`/proc/net/softnet_stat`) | SPAN 구성 완전성 |
| 큐 체류 나이, heartbeat, DB 저장 성공 여부 | "원본이 없으니" payload 엔진 재현 |

**커널 drop 과 앱 drop 을 더하지 않는다.** 분모가 다르고 원인이 다르다.
합산하면 "애플리케이션 손실률" 이라는 이름으로 잘못된 숫자가 나온다.

## 원칙 5. AI 는 판단하지 않는다

AI 가 할 수 있는 것: 탐지 결과에 대한 설명, 오탐 후보 제안.
AI 가 할 수 없는 것: 승인, scope 결정, TTL 결정, 방화벽 변경.

`netwatcher/services/ai_analyzer.py` 에서 설정 쓰기 호출을 전부 제거했고,
제안 경로(`detection/proposals.py`)만 남겼다. 게이트 G0-2 가 정적으로 확인한다.

## 원칙 6. 확인하지 않은 것을 확인했다고 쓰지 않는다

이 원칙이 코드베이스 전체에서 가장 자주 등장한다.

| 상황 | 잘못된 처리 | 이 저장소의 처리 |
|-|-|-|
| OS 조회 실패 | "적용 안 됨" 또는 "적용 됨" | `unknown` — 판단하지 않음 |
| 근거 층 누락 | 없던 값을 채워 넣음 | `metadata["evidence"]` 에 누락 기록 |
| 차이 비교 불가 | "줄어든 것" 으로 보고 | `non_comparable_reasons` 로 사유 남김 |
| 정리 루프 | "차단 해제됨" | 만료와 GC 회수를 분리 기록 |

## 원칙 7. 측정하지 않은 것을 측정했다고 말하지 않는다

게이트는 기본적으로 **작동한다** 는 것을 확인한다. 그런데 이 저장소에는
**작동하지 않는 것을 확인하는 게이트** 가 있다.

```
G0-11 리플레이 격리        — 운영 경로로 나가는 통로가 0 인지
G0-12 강제 주장 정직성      — OS 를 건드리는 백엔드가 없는지
G0-13 스키마 정합성          — 마이그레이션과 스키마 정의가 일치하는지
```

G0-11 과 G0-12 는 실제로 결함을 심어 FAIL 을 확인한 뒤에 통과를 확인했다.
**검증하지 않은 게이트는 없다고 생각한다.**

## 원칙 8. 판정은 재현되어야 한다

게이트 결과가 개발자의 로컬 `.env` 에 따라 달라지면 그것은 판정이 아니다.
`scripts/gates.py` 는 `NETWATCHER_SKIP_DOTENV=1` 로 `.env` 유입을 막는다.

이 문제가 실제로 있었다: `config/default.yaml` 이 `web.host: 0.0.0.0` +
`auth.enabled: false` 로 자기 계약을 위반하고 있었는데, 로그인 설정이 들어
있는 PC 에서만 게이트가 통과했다. 배포 파일 자체는 위반한 상태였다.

## 추가할 때의 체크리스트

새 판단 로직을 추가할 때:

1. **근거가 없다면 무엇을 반환하는가** — `unknown` 을 반환할 경로가 있는가
2. **판정에 사유가 붙는가** — 사유 없는 상태를 노출하는가
3. **게이트로 확인되는가** — 게이트가 실제로 잡아내는지 (깨뜨려서 확인)
4. **테스트가 배선 실수를 잡는가** — 키 존재가 아니라 실제 값 을 확인하는가
5. **주석이 아니라 코드로 강제되는가** — 권한·격리는 주석이 아니라 검사다
