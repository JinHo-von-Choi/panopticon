# 기여 기준

이 문서는 기능을 추가하거나 변경할 때 확인할 제품 동작과 검증 기준을 다룹니다. 개발 환경과 실행 명령은 [개발 가이드](DEVELOPMENT.md)를 참고하십시오.

## 탐지와 관측

관측 범위와 입력 누락은 항상 함께 표시해야 합니다. 단순히 경보가 발생하지 않았다는 사유만으로 해당 관측 구간 전체가 안전하다고 안내해서는 안 됩니다. 누락률은 동일 단계와 동일 시간대의 수신 건수를 바탕으로 산출하며, 앱·커널·네트워크 장비에서 발생한 누락을 하나로 합산해 집계하지 않습니다.

정상 업무 경보의 심각도를 낮춰 잡을 때는 장치 소유 관계와 통신 상대, 서비스, 시각 및 전송량을 두루 확인하십시오. 확인이 불가능하거나 이미 유효 기간이 만료된 조건에는 이를 일절 적용하지 않습니다. 아울러 공격 입력이 정상 기준선에 그대로 학습되는 일이 없도록 관련 상태값과 회귀 시험 결과를 반드시 점검합니다.

## 변경과 승인

AI 및 분석 역할은 설명과 제안 작성만 담당합니다. 설정 쓰기와 승인 작업에는 반드시 관리자 권한이 요구됩니다. API가 수행하는 권한 검증 절차는 실제 시스템 변경 경로와 정확히 맞물려야 합니다.

설정 후보군에는 기준값과 비교 결과를 직접 연결해야 합니다. 현재 설정이 중간에 바뀌었거나 공격 관측 범위를 누락시키는 후보는 시스템에 반영하지 마십시오. 파일 저장이나 엔진 재생성에 실패했을 때는 이전 설정과 기존 엔진 상태를 온전히 보존한 채 즉각 실패 응답을 반환합니다.

## 저장과 외부 효과

각 단계의 처리 결과를 끝까지 추적합니다. DB 확정 저장, 패킷 파일 생성, 알림 전달, OS 차단은 각각 독립적으로 결과를 확인해야 하며, 저장이나 전달 성공 응답을 온전히 수신하지 못한 상태를 성공 처리로 넘겨서는 안 됩니다.

재시도를 지원하는 저장 작업은 고유 식별자를 활용해 중복 기록을 방지합니다. 원격 전달이나 방화벽 제어 조치는 응답이 유실되었을 때 동일 작업이 중복 실행되어 미칠 영향을 미리 계산해 두어야 합니다. 대기열, 메모리, 파일, 처리 시간 전반에는 명확한 상한을 설정하십시오.

## 방화벽과 권한

제어 대상과 관리 경로에 미치는 영향, 만료 시간, 복구 경로를 사전에 점검합니다. 실제 트래픽이 지나는 경로를 직접 통제할 수 있는 위치에서만 차단 동작의 실효성을 검증해야 합니다. 단순 미러링 센서의 로컬 방화벽 설정을 두고 네트워크 전체가 차단되었다고 설명해서는 안 됩니다.

외부 입력을 임의로 셸 명령에 전달해 실행하지 않습니다. 시스템이 공식 지원하지 않는 백엔드나 권한 구성을 마치 지원 기능인 것처럼 대외 문서에 명시하지 마십시오.

## UI와 문서

상태값 구분이 핵심입니다. 요청 중, 적용 완료, 실패, 확인 불가 상태를 시스템 화면에서 명확히 구분해 표시해야 하며, 화면이 갱신되는 과정에서 사용자가 지정한 필터나 선택 항목, 화면 초점이 제멋대로 흐트러지지 않도록 점검하십시오. 중요한 상태 정보는 단순 색상 표기에만 의존하지 않고 명확한 텍스트 문구를 병기해 전달합니다.

문서는 독자가 수행할 작업과 직접 확인해야 할 결과를 중심으로 서술하십시오. 엔지니어 개인 경로, 비공개 접속 정보, 개발 일지, 실행 로그 덤프를 사용자 가이드에 포함해서는 안 됩니다. 기능 설명 내용은 현재 동작하는 코드 구현과 글자 그대로 일치해야 합니다.

## 검증

변경 사항과 맞물린 단위 시험, 마이그레이션 점검, 출시 전 필수 검사를 누락 없이 수행합니다. 시험 절차 중 부득이하게 건너뛴 항목과 실제 장비가 반드시 필요한 항목은 명확히 구분해 작업 내역에 남기십시오. 특정 테스트 장비에서 짧게 수행한 합성 실험 결과를 전체 환경의 일반적인 성능 보증 근거로 활용하지 않습니다.
