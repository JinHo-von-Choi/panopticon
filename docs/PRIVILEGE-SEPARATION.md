# 실행 권한과 분리 배포

패킷 캡처와 방화벽 조작은 일반 웹 서비스보다 큰 권한이 필요합니다. Panopticon을 배포할 때는 관리자 접속 범위와 센서가 사용하는 권한을 함께 검토해야 합니다.

## 현재 배포 방식

제공된 Docker 구성은 호스트 네트워크와 `NET_RAW`, `NET_ADMIN` 권한을 사용합니다. 호스트 서비스 예시는 root로 실행합니다. 웹/API와 센서를 서로 다른 사용자로 나누는 배포 방식은 아직 제공하지 않습니다.

관리 인터페이스는 기본적으로 루프백 주소에 열립니다. 다른 장치에서 사용할 때는 인증과 HTTPS를 설정하고 접근 가능한 관리망을 제한하세요. 자동 차단은 기본적으로 꺼져 있습니다.

## 분리 배포의 목표

분리 배포는 웹/API가 패킷 캡처와 방화벽 명령 권한을 직접 갖지 않도록 하는 방식입니다.

| 구성요소 | 역할 |
| --- | --- |
| 웹/API | 조회·제안·승인과 사용자 인터페이스 |
| 센서 | 지정 인터페이스의 캡처·탐지와 관측 상태 전달 |
| 차단 실행기 | 검증된 대상·범위·만료 시간의 조치와 결과 확인 |

구성요소 사이에서는 정해진 형식의 메시지만 허용하고, 연결 주체·크기·버전·중복을 검사해야 합니다. 차단 실행기는 승인과 현재 IP/MAC 소유 관계를 다시 확인하며 임의 명령을 받지 않아야 합니다.

이 구성은 향후 배포 설계입니다. 현재 버전에서 별도 프로세스 실행 명령이나 완성된 분리 배포 파일을 제공하지 않습니다. 제공된 배포에 없는 권한 구성을 임의로 가정하지 마세요.

## 실제 차단을 사용할 때

센서가 해당 트래픽 경로를 제어할 수 있는지, 관리자 접속을 잃었을 때 복구할 수 있는지 확인합니다. 적용·만료·재시작 후 상태를 실제 OS에서 검증해야 합니다.

SPAN은 관측용 복사본을 전달합니다. SPAN 센서의 로컬 방화벽을 바꿔도 다른 장치끼리의 원래 통신이 차단되는 것은 아닙니다.
