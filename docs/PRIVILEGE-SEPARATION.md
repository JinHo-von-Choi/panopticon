# 실행 권한과 분리 배포

Panopticon은 기본적으로 Suricata EVE 로그를 읽는 조사 콘솔입니다. 직접 패킷을 캡처할 때는 웹 콘솔과 센서를 별도 프로세스·계정으로 분리하여 실행합니다.

## 구성 선택

| 구성 | 권한과 역할 |
| --- | --- |
| EVE 콘솔 | 일반 사용자로 로그를 읽고 사건을 저장·조사합니다. 패킷 캡처와 OS 차단 권한이 없습니다. |
| 직접 캡처 콘솔 | 일반 사용자로 조회·업무 판정·승인을 처리합니다. 패킷 소켓과 방화벽 명령을 사용하지 않습니다. |
| 직접 캡처 센서 | 지정 인터페이스를 캡처·분석합니다. `NET_RAW`가 필요하며 `NET_ADMIN`은 부여하지 않습니다. |
| 독립 실행기 | 승인된 조치의 실행 의도와 결과를 기록합니다. 현재 제공하는 `shadow` 모드는 OS 방화벽을 변경하지 않습니다. |

EVE 설치는 [설치 안내](INSTALL.md)와 [EVE 연결](EVE.md) 문서를 따릅니다. 직접 캡처 환경에서는 설치 도구가 생성한 개별 설정과 전용 DB 계정을 사용해야 합니다. 배포 방식에 따라 Docker Compose 절차는 [설치 안내](INSTALL.md)를, systemd 구성은 [직접 캡처 서비스 설치](NATIVE-SYSTEMD.md)를 참조하십시오.

## 웹과 센서 사이의 경계

콘솔은 센서 제어 소켓에 오직 사전에 허용된 조회 및 설정 변경만 요청합니다. 센서는 연결 사용자의 UID, 현재 관리자 계정·권한, 설정 버전과 요청 크기를 철저히 검증합니다. 요청 의도를 감사 기록에 남긴 뒤 실제 변경을 수행하며, 적용 결과를 온전히 확인하지 못하면 성공 응답을 반환하지 않습니다.

센서와 콘솔은 분리된 DB 계정으로 격리하여 운영합니다. 센서 설정 및 증거 저장 공간 역시 콘솔 영역과 엄격히 분리해 보관합니다. 마이그레이션 계정은 설치나 업그레이드 단계에만 한정하여 사용해야 합니다. 설치 도구가 생성한 비밀번호와 환경변수 파일은 외부에 공개하거나 저장소에 커밋하지 않도록 각별히 유의하십시오.

## 접속과 차단

관리 접속은 호스트 루프백 주소에만 기본으로 바인딩됩니다. 외부 장치에서 접근해야 한다면 사용자 인증, HTTPS 암호화, 관리망 접근 제한을 반드시 사전에 구성하십시오. 직접 캡처 센서가 호스트 네트워크를 사용하는 것은 패킷 관측상 불가피하므로, 캡처 대상 인터페이스와 호스트 접근 권한 범위를 면밀히 함께 검토해야 합니다.

SPAN은 단순 관측용 트래픽 복사본입니다. 센서의 로컬 방화벽 규칙을 바꾼다고 해서 장치 간 본래 통신 흐름이 차단되는 것은 결코 아닙니다. 실제 OS 차단 조치는 트래픽 인라인 경로, 대상 호스트, 세션 만료, 재시작 복구 동작까지 완벽히 검증된 격리 구성에서만 신중하게 판단해야 합니다. `shadow` 모드의 실행 결과를 실제 방화벽 차단 완료의 증거로 삼아서는 안 됩니다.
